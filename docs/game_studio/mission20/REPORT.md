# Mission #20 — Game Studio multi-assets, qualification cloud

Le résultat vérifié est une **recette de garage Blender** dans la véritable API et la page Game Studio d'APEX. Une mission parente APEX coordonne trois missions graphiques persistantes, avec dépendances voiture → bâtiment → fauteuil, puis assemble leurs GLB validés en une scène Blender. Il s'agit d'une recette fixe explicitement annoncée, pas encore d'une décomposition libre par l'IA. Aucun résultat Unreal, CUDA ou véhicule pilotable n'est revendiqué.

## Exécution réelle

- Profil isolé : `/workspace/game-studio-output/mission20-qualified`, projet `f5a269ae-4a72-4646-b900-a39221984067` ; Blender 4.3.2 et Qwen2.5-Coder-7B-Instruct Q5_K_M local (commit `13fb94b`, SHA256 des poids `586844eac4d6d6321689f0192c8aa8e69cd8625974a5cc2d925b1a03366e4d16`). Les GLB retenus sont réimportés dans un quatrième processus Blender pour la scène. Les tâches déjà validées n'ont pas été relancées lors des reprises après deux erreurs de l'assembleur (parsing des arguments, puis débruitage OIDN indisponible en mode headless). Les erreurs et les reprises sont conservées dans [le reçu de mission](evidence/api-project.json).

## Intégration et garde-fous

`GameStudioProjectService` conserve l'identifiant parent, les missions filles, dépendances, événements, révisions, artefacts et décisions techniques. Les statuts sont lus dans `MissionService` et les enfants existants sont vérifiés avant toute reprise. Les endpoints authentifiés `/api/v1/game-studio/projects` (GET/POST), `/{id}` (GET), `/{id}/cancel`, `/{id}/resume`, `/{id}/improve-framing` et `/{id}/artifacts/{hash}` exposent ce parcours et les deux versions de scène. L'assembleur est un script Blender fixe autorisé par le catalogue, sans exécution de code arbitraire issu de Qwen. L'entrée refuse les références visuelles sur cette recette, puisqu'aucun pixel n'est interprété. UE5 est refusé au lancement du parcours Blender et le CPU doit être choisi explicitement en absence de CUDA.

La page Game Studio existante lance et suit la recette, affiche les trois tâches et leurs dépendances, les rendus, fichiers, verdicts, historique et capacités. Les deux cases juges/corrections sont indépendantes ; les contrôles obligatoires d'intégrité restent actifs. La correction reste bornée par le nombre de versions, le temps, les ressources et la portée de l'objet. La révision de cadrage est une action API bornée à une seule reconstruction et conserve la première version. L'application utilise toujours son frontend et son backend habituels ; la validation du launcher Windows reste impossible dans ce cloud.

## Validation et limites

Les 30 tests API/contrat/correction ciblés et 94 tests de régression Blender, Game Engineer, missions et packaging passent. Les 174 tests frontend passent ; son build et la vérification du runtime incluent le nouvel assembleur. Le navigateur Chromium headless a ouvert la page réelle, sélectionné la mission, chargé les rendus et affiché ses versions : [écran Game Studio](evidence/ui-game-studio.png), [suivi du projet](evidence/ui-project-detail.png), [scène affichée](evidence/ui-scene.png). Cette vérification a révélé puis permis de corriger un défaut réel : l'API servait les PNG en HTTP 200, mais la CSP historique de l'interface interdisait les URL `blob:` ; les images utilisent maintenant des URL `data:` déjà autorisées. [Contrôle des téléchargements authentifiés et des SHA256](evidence/api-artifact-check.json). Les fichiers binaires et les journaux ci-dessus proviennent d'exécutions Blender réelles, non de tests doubles. Les journaux d'échec et de reprise sont dans le profil cloud isolé ; les reçus exposent leurs événements.

Restent **BLOCKED** : Windows/UE5.8 et validation d'import/rendu en moteur ; RTX/CUDA, mesures VRAM et chemin GPU TripoSR ; véhicule pilotable et physique ; contrat de roues. Restent **non implémentés ou non qualifiés** : planification libre de demandes complexes, verrouillage inter-processus des projets, connexion canonique de ces jobs à `ProjectService`/`TaskLoop`/`Scheduler`, ingestion visuelle des références, jugement esthétique calibré, traitement vidéo/documents, génération neuronale 3D depuis cette recette, GPU first vérifié sur NVIDIA, scènes urbaines arbitraires et tests du launcher Windows. Le modèle local ne remplace pas silencieusement TripoSR : aucune génération neuronale n'est incluse ici. L'expérience suivante utile est de produire un GLB voiture conforme au contrat de roues, puis de qualifier séparément CUDA/TripoSR et UE5 sur le PC quand il redeviendra disponible, sans toucher `C:\GameProject`.

Reproduction dans un environnement muni de Blender, des dépendances Python et du manifeste local des poids : `python scripts/game_studio/demo_project.py --output /chemin/isole --manifest /chemin/coder-model.json`. Le script appelle l'API authentifiée d'APEX dans un profil temporaire ; il ne télécharge aucun poids et refuse le projet personnel.
