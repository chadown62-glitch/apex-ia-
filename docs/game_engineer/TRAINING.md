# Adaptation UE5 : prérequis avant entraînement

La baseline réellement exécutée est une génération locale Qwen2.5-Coder-7B-Instruct Q5_K_M de code UE5 candidat. Aucun Unreal Editor, SDK ou compilateur Unreal n’a exécuté ce code : qualification API, Blueprint, Chaos, compilation et corrections restent BLOCKED. Le dataset de tâches UE exécutées/compilées contient donc zéro exemple qualifié, et le texte candidat a `training_eligible=false`.

Licences du modèle : Apache-2.0 vérifiée avant téléchargement en #9, même GGUF officiel immuable. Pas de téléchargement des sources du moteur Epic ni d’exemples tiers. Les scripts et demandes du lot sont créés pour la mission autorisée ; aucun droit de redistribution externe n’est inventé. Le petit dataset Blender de #9 ne suffit pas à spécialiser un programmeur UE. Les recettes de modules Unreal et les API ne doivent pas être jugées sur le seul texte du modèle.

Après accès au moteur cible : fixer version UE/plugins/SDK, exécuter des familles Actor/Pawn/Chaos/caméra/inputs/import/Blueprints, compiler, conserver erreurs et corrections, vérifier une conduite automatisée. Collecter uniquement les projets/exemples autorisés, conserver leurs licences et provenance, et exclure les sources Epic non redistribuables du dataset partagé. Préassigner des familles heldout et leurs erreurs avant entraînement, éviter de réutiliser leurs corrections comme training. Mesurer base, réparation et adaptateur sur ces mêmes tâches inédites et sur le même moteur/matériel.

Une LoRA BF16 7B ne tient pas dans 8 Go avec ses seuls poids. Une QLoRA 4 bits est une candidate à mesurer, pas une preuve de faisabilité : poids environ 3,5–4 Go plus activations, quantification, adaptateurs/optimiseur, runtime CUDA et checkpoints. RAM 16 Go et VRAM 8 Go, aucun modèle simultané avec UE/Blender, contexte court, batch 1, petit rang et accumulation à étudier. Le GGUF Q5 n’est pas une base de fine-tuning ; partir des poids originaux autorisés, conserver la révision, puis exporter/quantifier l’adaptateur fusionné en GGUF et revalider les tâches réelles avant promotion. Aucun poids original/adaptateur téléchargé ou entraîné ici.

Conserver base, dataset/adapter SHA et rapports versionnés ; retour à la base officielle sans destruction. Aucun gain avant/après fine-tuning n’est revendiqué. Entraînement lourd bloqué par l’absence de baseline UE qualifiée, de données suffisantes et de mesures mémoire/calcule sur la cible.
